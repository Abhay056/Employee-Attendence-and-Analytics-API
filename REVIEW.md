# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | Global / Lines 22–24 | No database indexes are created on startup. Lack of unique constraints on `emp_code` and `(emp_code, date)` allows duplicates, and queries cause collection scans (`COLLSCAN`). | Concurrent employee or punch-in requests create duplicate records; queries on 100k records time out. | Added an `@app.on_event("startup")` hook to idempotently create unique indexes on `employees.emp_code` and `attendance_logs.(emp_code, date)`, plus indexes for date ordering and lookup. |
| 2 | `health()` / Line 73 | Returns static `{"status": "ok"}` without verifying MongoDB database connectivity. | Stop MongoDB service or configure invalid `MONGO_URI`; `GET /health` continues returning 200 instead of 503. | Added `db.command("ping")` within try/except block; raises `HTTPException(503)` if ping fails. |
| 3 | `compute_late_minutes()` / Lines 35–37 | Replaces hours directly on UTC datetimes without converting to IST; truncation comparison `minutes > 10` fails on 10m 30s (evaluates `10 > 10` as False); ignores overnight shifts. | Punch-in at 09:40:01 for a 09:30 shift returned 0 late minutes instead of 10 (R2). | Converted `punch_in` to IST; computed elapsed seconds from shift start; if elapsed seconds > 600, returned `int(elapsed // 60)` (floor); added overnight shift support. |
| 4 | `compute_work_hours()` / Line 41 | Uses Python's built-in `round()`, which performs round-half-to-even (banker's rounding) instead of round-half-up (R4, R8). | Work duration of 2.125 hours rounds to 2.12 instead of 2.13. | Replaced with `Decimal.quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)`. |
| 5 | `compute_overtime()` / Lines 46–47 | Misses R3 30-minute minimum threshold (counts 1–29 minutes); compares offset-aware IST datetime with naive UTC datetime causing `TypeError`; fails across midnight for overnight shifts. | Punch-out 15 minutes after shift end returned 15 overtime minutes instead of 0; naive vs aware comparison crashed with `TypeError`. | Normalized timezones to IST, rolled overnight shift end to next calendar day, and enforced 0 if overtime < 30 minutes. |
| 6 | `create_employee()` / Lines 79–83 | Check-then-insert pattern (`find_one` then `insert_one`) has a race condition allowing duplicate employees; `created_at` uses local system time. | Concurrent `POST /employees` requests with identical `emp_code` both succeed and create duplicate documents. | Relied on unique index on `emp_code`, caught `DuplicateKeyError` to return 409, and stored UTC datetime. |
| 7 | `list_employees()` / Lines 93–95 | `skip = page * page_size` skips the first page entirely when `page=1` (skips 20 docs); `total` ignores department filter; items not sorted by `emp_code`. | `GET /employees?page=1` returns items 21–40; department-filtered queries report global total employee count; sort order is non-deterministic. | Changed to `skip = (page - 1) * page_size`, passed filter `q` to `count_documents(q)`, and sorted by `emp_code` ascending. |
| 8 | `punch_in()` / Line 101 | Does not check if `db.employees.find_one(...)` returns `None`. When employee is missing, `emp["shift_start"]` crashes with unhandled `TypeError` (HTTP 500). | Punching in with a non-existent `emp_code` returns HTTP 500 instead of 404. | Added explicit check `if not emp: raise HTTPException(404, detail="Employee not found")`. |
| 9 | `punch_in()` / Lines 104–118 | Check-then-insert (`find_one` then `insert_one`) allows concurrent punch-ins to slip through and create duplicate records for the same employee-date. | Two parallel punch-in calls for the same employee and day both succeed with 201. | Enforced unique compound index `(emp_code, date)` and caught `DuplicateKeyError` to return 409. |
| 10 | `punch_in()` / Lines 102–103 | Uses local system date `ts.date().isoformat()`, violating R1 for overnight shifts where a punch-in before `shift_end` belongs to the previous calendar day. | Overnight shift punch-in at 01:00 IST for a 22:00–06:00 shift was assigned today's date instead of yesterday's shift date. | Converted punch timestamp to IST and implemented overnight shift date resolution per R1. |
| 11 | `punch_in()` & `list_attendance()` / Lines 119, 149 | Sets `doc["id"] = str(res.inserted_id)`. The OpenAPI contract and problem statement forbid `id` in attendance records (addressed only by `emp_code` and `date`). | Response validation fails against OpenAPI `AttendanceRecord` schema due to extra `id` field. | Removed `id` from attendance responses. |
| 12 | `punch_in()` & `list_attendance()` / Lines 106–128, 144–150 | Returns Python datetime objects in responses (serialized to ISO strings) instead of integer epoch milliseconds. | Returned `"2026-07-06T09:30:00"` instead of epoch milliseconds integer `1783310400000`. | Converted all instants (`punch_in`, `punch_out`, `created_at`, history `at`) to integer epoch milliseconds. |
| 13 | `list_attendance()` / Lines 144–147 | Fetches entire collection into Python memory (`list(db.attendance_logs.find(q))`), then sorts and slices in Python. | Server runs out of memory or times out when querying 100k records. | Delegated sorting, pagination, and counting to MongoDB via `.sort([("date", -1), ("emp_code", 1)]).skip(...).limit(...)` and `count_documents(q)`. |
| 14 | `PunchInIn` / Line 66 | Accepts arbitrary strings for `status` (e.g., `ABSENT`, `LEAVE`), allowing invalid presence states to be created via punch-in. | Punching in with `{"status": "LEAVE"}` succeeded with 201 instead of 422. | Added validation restricting punch-in status strictly to `{"PRESENT", "WFH", "ON_DUTY"}` and returning 422 for others. |

## Items examined and determined NOT to be defects

1. **`IST = timezone(timedelta(hours=5, minutes=30))`**: Indian Standard Time does not observe Daylight Saving Time (UTC+05:30 year-round). A static offset is completely accurate, performant, and avoids third-party tzdata dependencies.
2. **`db.employees.find(q, {"_id": 0})`**: Projecting out `_id` is correct because MongoDB's internal ObjectId must not be exposed in the API contract.
3. **Empty `history: []` on initial punch-in**: Correct per DATA_MODEL.md section 4, as `history` is an audit trail exclusively reserved for manual corrections (PATCH).
4. **Returning HTTP 409 for duplicate punch-in**: Correctly aligns with OpenAPI specification and HTTP conflict semantics.
